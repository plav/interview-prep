#DOC Programming Fundamentals
#SHEET Basics
I What's the difference between static and dynamic typing? || Static typing (Java, C#, TypeScript) checks types before the code runs, so many mistakes are caught at compile time and editors can help more. Dynamic typing (Python, JavaScript) checks types as the code runs, which is more flexible but surfaces errors later. Python with type hints and a checker sits in between.
I What's the difference between strong and weak typing? || It's about implicit conversions. Python is dynamically typed but strong: `"5" + 1` is an error. JavaScript is weak: `"5" + 1` silently becomes `"51"`. Java and C# are static and strong.
I What happens when an integer gets too big? || In Java and C#, it silently wraps round to a negative number unless you use checked arithmetic or a big-number type. Python integers grow without limit. JavaScript numbers lose precision beyond 2^53, so use `bigint` for very large values.
I Why does `-7 / 2` give different answers in different languages? || Java, C# and JavaScript's `Math.trunc` round towards zero, giving -3. Python's `//` rounds down (floor), giving -4. This matters for things like bucketing and pagination with negative numbers.
#SHEET Functions
I What is a closure? Give a real use. || A function that keeps access to variables from the scope where it was created, even after that scope has finished. It's used for factories like `makeDiscount(rate)`, callbacks that need context, memoisation and private state.
I What is a higher-order function? || A function that takes a function as an argument or returns one, such as `map`, `filter`, sort comparators, decorators and middleware. They let you separate what to do from how often or when.
I What is a pure function, and why does it matter? || Its output depends only on its inputs and it has no side effects. That makes it easy to test, cache and run in parallel, and easy to reason about. Keep business rules pure and put I/O at the edges.
I Pass by value or pass by reference? || Java, Python and JavaScript always pass a copy of the value, but for objects that value is a reference. A method can therefore mutate the object, but reassigning the parameter doesn't affect the caller. C# behaves the same by default and offers real pass-by-reference with `ref` and `out`.
I Overloading or overriding? || Overloading means several methods with the same name and different parameters, resolved at compile time; Java and C# support it, Python doesn't. Overriding means a subclass replacing a parent's method, resolved at runtime.
#SHEET Classes and objects
I What's the difference between a class and an object? || A class is the blueprint that defines fields and methods; an object is an instance created from it, with its own field values. There's one `Product` class and many product objects.
I What does a constructor do? || It runs when an object is created and sets up a valid starting state. That's the best place to validate inputs, so an invalid object can never exist.
I When would you make something static? || When it belongs to the type rather than to any one object: constants, factory methods and pure helper functions. Avoid static mutable state, because it's effectively global.
I What are the four pillars of object-oriented programming? || Encapsulation (hide internal state behind methods), abstraction (expose what something does, not how), inheritance (reuse and specialise a parent type) and polymorphism (one interface, many implementations, chosen at runtime).
I Records or classes? || Use records (or dataclasses) for immutable data compared by value, such as DTOs, events and money. Use classes for things with identity and behaviour that changes over time, such as an account or an order being processed.
#SHEET Encapsulation
I What is encapsulation, and why does it matter? || Bundling data with the methods that operate on it, and hiding the data so it can only change through those methods. It protects invariants, such as a balance never going negative, and lets you change the internals without breaking callers.
I Is a class with a getter and setter for every field encapsulated? || Not really. If every field can be set freely, the class can't enforce its rules; it's a data structure with extra syntax. Real encapsulation exposes intention-revealing operations (`withdraw`) rather than raw state (`setBalance`).
I Encapsulation or abstraction? || Encapsulation hides data and protects how state changes. Abstraction hides complexity behind a simple interface, describing what something does rather than how. They work together: a well-encapsulated class usually offers a good abstraction.
I How do you make a class immutable in Java or C#? || Make fields `final` or `readonly`, validate in the constructor, provide no setters, return new objects for changes, and copy any mutable inputs and outputs. In Java, also make the class `final`. Records give you most of this for free.
I How private is "private" in Python and TypeScript? || Python privacy is a naming convention: `_name` means internal, and `__name` is name-mangled but still reachable. TypeScript's `private` is checked only at compile time, while `#name` fields are private at runtime. Java and C# enforce access in the compiler and runtime, although reflection can still get around it.
